# 一、已确认（用户已裁定，非技术建议）

## 1.1 三项边界（r3「用户已确认」块，2.6 明确不再作为阻塞门禁）

1. **勘察判定**：勘察对象存在即不能拆（含复制带来的 `survey`，不得伪装成未勘察；**不得用时间戳判断「是否可靠保存」**）；只打开勘察、未保存，仍可拆；空对象 `{}` 以及非对象却存在的值（数组、字符串等）视为异常：**拒绝拆分并提示核查**，不自动清理，也**不顺改**既有勘察界面的「已勘察」判定。
2. **出票范围**：拆分可选，不拆也能执行；必须在勘察、出票之前拆。本轮**不造出票功能或出票状态**；业务原则仍是出票前拆分，但系统当前**仅能按已保存勘察拦截，无法检测线下或系统外出票**，将来出票功能接入后再校验。**不得伪造出票信号，也不得把本轮门禁当成全局合规承诺。**
3. **旧拆分**：来源保留，**不恢复、不迁移**；**关闭撤销入口和 API**；**解除「改起止须先撤销」**；**已拆过的原记录不再重复拆**（来源首日标识与子记录来源要区别）；复制出的新计划**不继承拆分限制**；若带 `survey`，仍按已勘察拦截，**不得偷偷去掉 `survey`**；其他合法月生周来源不动；旧 `splitSnapshot` **留作审计，不可用于恢复**；用户未要求新增人工恢复能力。复制的「真实原始来源」与现有 `parentPlanId`（拆分复用）的区别由 Step 1 核实，**不在此自动新造字段**。

## 1.2 拆分行为（r3 已定块）

- 拆前**预览每日日期、工作内容、工量**；**预览与确认均须按勘察/已拆规则拦截**，不能只在最终确认拦截。
- 确认后**原记录作为首日**，其余生成**独立日计划**；**单向，不提供撤销或父子回滚**，拆错则取消相关日计划再开周计划；**来源可追溯但不等于可回滚**。
- 拆分前置：暂保持仅周计划可拆；「未执行」「跨天」是否仍附加待确认（**不建状态机**）；已拆原记录不可再拆（已定）；取消父子回滚与改期约束；父不改名、收缩第一天、子名「（M月D日）」暂沿用既有命名；父有勘察则复制给子计划一条**已被「勘察对象存在即不可拆」替代**（成功路径只共用勘察编号、**不复制勘察记录**）；**撤销四条全部废止**；`unsplit` 入口与 API 关闭。

## 1.3 编号 / 取号年月 / 耗尽规则（r3 已定块）

- 配电第一种 / 第二种 / 低压工作票编号 = **`YYYYMM` + 一位类型码（6 / 7 / 9，不加 0）+ 流水从 801 起**，**按月按票种独立**；**首日保留原工作票号，其余独立日计划各取新工作票号**。
- **拆分各日共用原勘察编号，不为子记录新取勘察号**；此为**合法共号**，不得把「全部日计划勘察号全局唯一」强加为约束，**历史撞号须与合法拆分共享相区别**（见 §四）。
- **新建与复制的取号年月沿用「操作当天」所属月份；拆分新增日计划的工作票号按其「开始日期」所属月份取号，首日原工作票号不变。**
- **月份一律按 Asia/Shanghai 业务时间计算**（Step 1 换算事实见 `PLAN.md` §4：服务端 `todayBizDate()` = `bjStr().slice(0,10)` → `YYYYMM`；各日开始日期取 `date.slice(0,7).replace('-','')`，字面业务日期不做 UTC 换算）。
- **某月某票种 801～999 用完则停止取号并明确提示，不重复、不扩位、不跨月借号。**
- 线路票种**无新裁定，不扩展**；**不新增未经确认的带电票种**；历史 11 位配电工作票号**不进入新流水**；新旧码表必须分开；只对**存活记录**取工作票号（软删号可复用按既有口径，本轮不改）。
- 勘察编号的**既有格式与新建/复制取号规则保持不变**（`YYYYMM` + 3 位从 001 起）；本轮只把拆分时的勘察号处置定为「各日共用原号」。

## 1.4 本轮不做 / 不改（r3 1.3 保护范围）

不做：计划列表排序、计划状态机、月计划结算编辑、**出票功能或出票状态**、R1–R8、生产清理、历史号重编、新增人工恢复拆分、自动清理异常 `survey`。不改：人员冲突口径、日历（只显示周计划、排除归档/取消/执行/结算、未来 21 天）、`PlanDateTime`、月计划**列表 12 列**定版与导入导出 20 列规格、勘察 17 槽位模板及原地覆盖（`server/core/survey-doc.js`）、既有勘察界面「已勘察」判定、线路既有编号。改界面须兼顾 iPhone 390 宽；生产只读；无 push / tag / Release / CI / 合并授权。
