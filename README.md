# 电网生产ERP管理系统（本地自托管版）

> 一套可完全离线运行、数据全部保留在本机的电网生产业务管理系统。
> 覆盖从项目立项、计划排期、借工调度，到竣工资料、文档中心与材料台账的核心生产管理流程。

---

## 一、产品简介

本系统是一个 **本地自托管** 的电网生产 ERP：

- 无需联网、无需云端账号，所有数据保存在本机文件中；
- 覆盖工程项目全生命周期的生产管理场景；
- 采用零构建架构，开箱即用，便于二次开发与内网部署。

**首次启动即为纯净空实例**：不含任何演示数据。企业名称、年度计划、属地供电所、班组、人员、项目、材料等均需在登录后自行录入。

**默认管理员账号**：`admin / admin123`（角色：超级用户）。首次登录后请尽快修改密码，并在「全局设置」中填写企业名称等基础信息。

---

## 二、技术栈

- **后端**：Node.js + Express，本地 JSON 文件存储（`data/db.json`，零外部数据库依赖，最大可移植）
- **前端**：Vue 3 + Element Plus
  - 采用**离线运行时全局构建**（`public/vendor/` 内置 `vue.global.prod.js`、`element-plus.full.min.js`、`element-plus.css`）
  - 运行时模板编译，**无需 webpack/vite 等打包工具**，浏览器直接打开即可
- **鉴权**：轻量级 Bearer Token（登录后存 `localStorage`）
- **部署**：支持原生 `node` 启动，也支持 Docker 一键部署

## 三、快速开始

### 1. 安装依赖

```bash
npm install      # 仅依赖 express / multer / xlsx
```

### 2. 启动

```bash
npm start
# 或自定义端口： PORT=8080 npm start
```

启动后控制台输出：

```
电网生产ERP（本地版）已启动
➜  本地访问: http://localhost:5173
➜  默认账号: admin / admin123  (角色: 超级用户)
```

### 3. 打开使用

浏览器访问 **http://localhost:5173** ，用默认账号登录即可。

> 手机端已做 iPhone 系列自适应适配，可在同一局域网内用手机浏览器直接访问（请使用本机局域网 IP 或 `.local` 域名，而非 `localhost`）。

## 登录页背景

登录页采用「全屏背景图 + 毛玻璃卡片」布局，背景可在 **全局设置 → 登录界面** 中更换：

- **三张内置预设**：草原雪山（高原草甸 · 远山雪线）、冰川落日（冰原浮冰 · 暖阳天际）、层峦叠嶂（青蓝山峦 · 晨雾光影），统一处理为 **2560×1440**（Lanczos 重采样 + 轻度锐化，减轻高分屏放大发虚），随镜像分发，无需额外配置；
- **无闪跳 / 无黑屏**：首页由服务端直出，把当前背景直接写进 HTML 的 CSS 变量 `--login-bg`，并同时注入**平均色底**与 **LQIP 超小模糊占位图**（`--login-bg-color` / `--login-bg-lqip`）+ `rel=preload`；首帧即为所选背景的颜色/轮廓，图片字节到达后无缝替换，不会出现「黑一下」或「先默认图再切换」；
- **壁纸式铺展方式**：填充（cover）/ 适应（contain）/ 拉伸（stretch）/ 平铺（tile）/ 居中（center），对应 `settings.loginBgMode`，服务端直出到 `.login-bg-layer` 的 `background-size/repeat`；
- **旋转**：`settings.loginBgRotate` 支持 0° / 90° / 180° / 270°，手机或相机照片方向不对时可一键转正；90°/270° 会自动交换宽高并居中，保证旋转后仍铺满视口；
- **实时预览**：设置页提供 1:1 预览框，切换背景、铺展方式或旋转角度即时呈现；
- **删除自定义背景**：`DELETE /api/settings/login-bg` 删除磁盘文件并恢复默认预设；设置页仅在当前为自定义上传时启用该按钮；
- **本地上传**：支持 JPG / PNG / WebP / GIF，单张不超过 10MB，建议 1920×1080 以上横图；上传后自动应用，并由浏览器 canvas 生成 LQIP 与平均色一并提交（旧上传图会在打开设置页时自动补算回填）；文件存 `data/uploads/login-bg/`，随 `./data` 卷持久化，镜像更新不丢失；新上传会重置旋转角为 0°；
- 上传后的背景通过 `GET /api/login-bg/:name` 免登录读取（登录页在鉴权前就需要取图），已做目录穿越防护，仅允许读取该专属目录；
- 登录页所需的系统名 / 企业名由公开接口 `GET /api/public-config` 提供（无需登录）。

## 六、数据存储与重置

- 所有数据保存在 **`data/db.json`**（项目、计划、借工、竣工资料、材料、领料单、导入批次、出库、作业人员、外部通讯录、年度计划、属地供电所、材料目录、班组、文档、用户、设置、登录令牌）。
- 数据**完全保存在本机，不上传任何云端**。
- **重置为初始空实例**：停止服务后删除 `data/db.json`，再次启动即自动重新初始化（所有业务数据清空，企业名称等需重新设置）。

### 代码与运行时数据严格分离（开发 / 提交环境数据隔离）

- 所有运行时数据（业务记录、用户上传附件、登录令牌）**只存在于 `data/` 与 `uploads/` 目录**，二者已被 `.gitignore`（不进 Git）与 `.dockerignore`（不进镜像）双重排除。
- 因此**本地开发时你可以随意录入示例 / 测试数据**：它们永远不会被推送到 GitHub，也不会被打包进 Docker 镜像，更不会在更新部署时污染群晖上的真实用户数据。
- **开发 ↔ 提交 双环境模型（推荐工作流）**：
  1. **开发环境（保留测试数据）**：`server.js` 的 `loadDB()` 仅在 `data/db.json` 不存在/损坏时才重新播种。**平时改代码、重启服务都不会清空数据**，录入的测试数据会一直留在本机 `data/db.json` 中，可连续测试。
  2. **提交 / 发布前（产出干净版本）**：在准备 `git commit` / 打 tag / `docker build` 之前，运行一次清理脚本：
     ```bash
     npm run scrub
     ```
     该脚本会先停掉本机 5173 服务，再删除 `data/db.json` 与清空 `data/uploads/`。下次 `npm start` 会自动 `seedDB()` 重建一个**干净的空实例**（仅 `admin/admin123`，不带任何测试数据），此后提交/打包均不会带入测试数据。
  3. 仓库内置 **CI 安全闸门**：每次推送会先扫描仓库，若发现 `data/`、`uploads/` 或 `db.json` 被意外提交，构建立即失败并提示移除，从源头杜绝数据混入。
- 更新部署时，镜像只携带代码；群晖侧 `./data` 卷保持不变，原有业务数据原样保留。

## 八、已知限制 / 可扩展方向

1. **鉴权为轻量级**：Token 存于内存并持久化到 `db.json`，适合本地 / 内网使用；如需生产级安全可替换为 JWT + 密码哈希。
2. **单实例部署**：为单一企业 / 班组自用设计，全部业务数据共用一份库、已删除记录走逻辑删除（置 `deleted`）；如需跨组织强多租户可另行扩展。
3. **材料台账「导入批次」** 目前作批次记录登记；「材料明细」已支持真实 Excel 导入。
4. 可将 JSON 存储平滑切换为 SQLite（`better-sqlite3`）以获得更高并发与查询能力。
